# 스프링 부트 실습 교재

이 교재는 자바를 배운 초급 개발자가 스프링 부트로 데이터를 다루고 웹 애플리케이션을 만드는 과정을 안내합니다. 클래스·인터페이스·메서드·기본 컬렉션 문법과 SQL·HTML의 기초를 알고 있다면 예제 프로젝트를 실행하며 학습할 수 있습니다.

스프링의 객체 관리에서 출발해 데이터베이스 연동, REST API와 요청 객체 검증, 웹 화면, 로그인과 권한 제어로 학습 범위를 넓혀 갑니다. REST API에서 검증 애너테이션과 기본 오류 응답을 익히고, MVC에서는 같은 검증 방식을 폼의 입력값 유지와 오류 메시지 표시로 확장합니다. 각 절에서는 필요한 개념을 먼저 익히고, 실제 코드와 실행 결과를 연결해 동작을 확인합니다.

## 실습 환경과 진행 방법

각 프로젝트를 새로 만들 때는 해당 장의 Spring Initializr 캡처를 보고 의존성을 선택합니다. 공통 설정은 Gradle - Groovy, Java, Group `com.example`, Artifact `demo`, Package name `com.example.demo`, Jar, Properties, Java 21입니다. Spring Boot 버전은 배포된 예제 프로젝트의 `build.gradle`을 기준으로 맞춥니다.

Generate로 내려받은 ZIP 파일을 압축 해제하고, 폴더 이름을 각 실습의 프로젝트 이름으로 정한 뒤 IntelliJ IDEA에서 엽니다. Gradle 의존성 다운로드가 끝나면 코드를 작성할 준비가 됩니다.

Spring Initializr 캡처는 각 프로젝트에 필요한 의존성을 확인하는 데 사용합니다. 3장의 spring-rest 프로젝트는 생성 단계에서 Validation을 함께 선택합니다.

**제공된 프로젝트로 학습하는 방법**

이 교재의 실행 결과는 제공된 예제 프로젝트를 기준으로 합니다. 먼저 해당 파일과 메서드를 찾아 코드를 읽고, 안내된 테스트나 HTTP 요청을 실행합니다. 이후 검색어·입력값·페이지 크기를 바꾸어 결과를 비교합니다. 새 프로젝트를 만들어 따라 작성한다면 같은 패키지와 클래스 구성을 준비하고, 기능별 메서드를 해당 클래스 안에 추가합니다.

클래스가 처음 등장할 때는 선언부와 필요한 주입 필드를 함께 살펴봅니다. 뒤에서 제시하는 메서드 발췌는 그 클래스에 속한 코드입니다. 생성자의 원리를 설명하기 위한 예시와 실행 결과 예시는 본문에 별도로 표시합니다.

- Java 21과 IntelliJ IDEA를 사용합니다. 각 모듈은 독립 Gradle 프로젝트입니다.
- 실행 코드와 의존성의 기준은 각 프로젝트의 실제 파일입니다. 코드 블록 위의 파일 링크로 원문을 열 수 있습니다.
- 파일 링크를 통해 패키지·import·클래스 선언을 확인할 수 있습니다. 메서드 발췌는 해당 클래스의 주입 필드와 함께 읽습니다.
- 앱은 각 프로젝트의 DemoApplication으로 실행합니다. 웹 모듈은 기본 8080 포트를 공유하므로 하나씩 실행합니다.
- JDBC·MyBatis·JPA·REST 앱은 MariaDB와 DB_URL·DB_USER·DB_PASS 환경변수를 사용합니다. JDBC·MyBatis·JPA 테스트에도 같은 환경변수를 적용합니다. REST의 Spring 테스트는 별도의 테스트용 H2 설정을 사용하며, Mockito 단위 테스트는 DB를 사용하지 않습니다.
- MVC·Security는 H2 메모리 DB를 사용하며 앱 종료 시 데이터가 사라집니다. spring-thymeleaf는 DB 없이 실행합니다.
- MyBatis·JPA는 @Test를 하나씩 실행하고 로그를 관찰합니다. REST 장에서 assertThat·MockMvc·Mockito로 자동 검증을 배웁니다.

## 데이터와 예상 결과의 기준

회원 샘플은 윤서준(10)·윤광철(43)·공미영(23)·김도윤(10)입니다. 이메일은 각 실습의 @campus.com 주소를 사용합니다. 신규 회원 실습은 정혁 / JungHyuk@campus.com / 10살입니다.

공통 SQL은 회원 4명과 게시글 100개를 준비합니다. MariaDB를 이어 쓸 때 data.sql을 중복 실행하지 않습니다. HTTP로 등록한 정혁이 남아 있으면 다음 등록·일괄 가입 실습 전에 삭제합니다. MyBatis·JPA 테스트는 종료 후 변경을 되돌리지만, DB가 발급한 자동 증가 ID까지 초기화하지는 않습니다.

| 실습 | 시작 상태와 실행 방법 | 실습이 끝난 뒤의 상태 |
|---|---|---|
| JDBC | 공통 샘플을 준비한 뒤 조회합니다. | 데이터를 변경하지 않습니다. |
| MyBatis·JPA | 공통 샘플이 있는 상태에서 테스트를 각각 실행합니다. | 테스트 안에서 등록·수정·삭제한 내용은 롤백됩니다. |
| REST 회원 CRUD | 정혁이 없는 상태에서 등록부터 삭제까지 이어서 실행합니다. | 새로 등록한 회원을 삭제하면 기존 회원 4명이 남습니다. |
| REST XML 통신 | 회원 CRUD의 삭제 후 members-xml.http를 순서대로 실행합니다. | XML 등록·조회 후 실습 회원을 삭제해 기존 회원 4명을 유지합니다. |
| REST 요청 객체 검증 | CRUD와 XML 실습의 삭제 후 members.http의 요청 13~17을 실행합니다. | 실패 요청은 저장하지 않으며, 정상 등록한 회원을 삭제해 기존 회원 4명을 유지합니다. |
| REST 게시글 CRUD | 회원 실습을 마친 뒤 게시글 하나를 등록해 조회·수정·페이징·삭제합니다. | 새 게시글을 삭제하면 기존 게시글 100개가 남습니다. |
| REST 일괄 가입 | 정혁이 없는 상태에서 중복 이메일 실패 요청을 실행합니다. | 트랜잭션이 적용되어 있으면 회원 4명이 유지됩니다. |
| MVC | 별도의 H2 메모리 DB에서 시작합니다. | 변경은 앱 실행 중 유지되며, 앱을 재시작하면 초기 샘플로 돌아갑니다. |
| Security | 로그인 계정 4명과 상품 2개가 있는 별도의 H2 DB에서 시작합니다. | 상품 변경은 앱 실행 중 유지되며, 앱을 재시작하면 초기화됩니다. |

본문의 **예상 결과**는 제공된 샘플과 각 실습의 시작 조건을 바탕으로 합니다. 로그 예시에서는 시각·스레드·클래스 이름을 생략하고 확인할 메시지만 제시합니다. JSON에 제시한 ID와 시각도 설명용 예시이므로, 실행할 때 받은 실제 값을 사용합니다. 데이터가 추가되면 개수와 페이지 수도 달라질 수 있습니다. 정렬 조건이 없는 목록의 순서는 비교 기준으로 삼지 않습니다.

Security는 로그인 회원 4명과 상품 2개의 전용 SQL을 사용합니다. 계정 비밀번호는 5장의 실습 계정 표를 참고합니다. 화면은 기본 HTML로 구성하며 자체 CSS는 사용하지 않습니다. MVC는 학습한 공통·페이징 fragment를 사용하고, Security는 화면마다 필요한 링크와 폼을 직접 작성합니다.

## 코드 읽기와 실행 결과 확인

실습마다 다음 세 가지를 먼저 확인합니다.

1. 어느 입력을 어떤 Controller·Repository·Mapper 메서드에 전달하는가?
2. 반환값은 엔티티·DTO·목록·Page·화면 이름 중 무엇인가?
3. 로그·HTTP 상태·화면·DB 중 어디에서 결과를 확인하는가?

실습 도중 문법을 모두 외우기보다 값을 한 개 바꾼 뒤 예상 결과와 비교해 봅니다. 테스트를 실행할 때는 다른 테스트의 실행 순서에 의존하지 않습니다. 외부 DB 실습에서는 연결 오류와 검증 실패를 구분합니다.

## Word 변환을 위한 문서 규칙

1장은 01 파일, 2장은 02 도입과 02-1·02-2·02-3 파일, 나머지는 03·04·05·06 파일 순서로 합칩니다. 이 README는 전체 안내입니다.

코드 블록은 java·sql·xml·properties·html·http·groovy 언어를 구분합니다. 코드와 설명을 함께 읽을 수 있도록 소절 단위로 구성했으며, 외부 링크를 클릭하지 않아도 주요 실습 코드와 예상 결과를 본문에서 볼 수 있습니다. 3장의 요청·응답 변환과 5장의 보안 필터 흐름은 Mermaid 다이어그램으로 표현했습니다. Mermaid를 지원하는 Markdown 미리보기에서 그림으로 볼 수 있으며, Word로 변환할 때는 그림으로 렌더링해 삽입합니다.
