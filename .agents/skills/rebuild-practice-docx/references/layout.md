# 프로젝트의 편집 형식

기존 배포판과 표지 DOCX를 디자인 기준으로 삼는다. 아래 수치는 `scripts/build-docx.ps1`에 구현된 현재 형식이며, 내용이 늘어 페이지가 바뀌는 것은 정상이다.

- Letter 612×792pt. 본문 여백 위 58pt, 아래 56pt, 좌우 67pt.
- 표지는 편집 가능한 원본 텍스트와 기존 Spring Boot 그림을 유지한다.
- 본문은 맑은 고딕 10.5pt, 제목은 24·15.5·12.5pt와 기존 짙은 녹색 계열이다.
- 코드는 Consolas 9pt, 한글은 맑은 고딕이며 줄간격은 12.25pt로 고정한다. 연한 배경을 사용하며 긴 코드는 페이지를 넘길 수 있다.
- 표 너비는 478pt, 머리행은 짙은 녹색 배경에 흰 글씨이며 반복 표시한다. 한 행을 두 페이지로 쪼개지 않는다.
- 캡처는 원본 이미지를 포함한 채 의존성 영역을 확대한다. 파일명별 확대 영역은 `Picture()`에서 관리하며 다이어그램에는 캡처용 자르기를 적용하지 않는다.
- 그림 설명은 그림과 같은 쪽에 둔다. 다이어그램은 기존 PNG를 재사용하고 인쇄 크기에서 글자를 확인한다.
- 장은 새 쪽에서 시작하며 머리말에는 현재 장, 꼬리말에는 책 제목과 실제 PAGE 필드를 표시한다.
- 목차는 Word의 제목 수준 1~2를 사용한다. 하위 실습 제목은 탐색 가능한 제목 수준 3으로 유지한다.

## 원본과 배포판 사이의 표현 차이

README의 Markdown 전용 목차·이전/다음 링크·Word 변환 규칙은 배포판에서 제외한다. 코드 앞의 파일 링크는 파일명과 프로젝트 상대 경로로 표시하며, Mermaid는 매핑된 그림으로 바꾼다. 그 밖의 장·절 순서와 본문, 코드, 표는 원문을 따른다.

## 도구를 고칠 때

- 장 목록·표지·출력 파일·Mermaid와 PNG의 대응은 `book.json`에서 관리한다.
- `build-docx.ps1`은 원본 표지의 OOXML을 유지하면서 본문과 스타일을 생성한다.
- `update-fields.ps1`은 별도 Word 인스턴스에서 실제 목차와 페이지 필드를 갱신하고 임시 PDF를 만든다.
- `verify-docx.ps1`은 코드 전체, 제목·표·그림 수, 표지 텍스트, 이미지 해시, 목차와 페이지 필드를 확인한다.
- `InspectBook.java`는 PDF의 모든 쪽을 이미지로 만들고 여백 밖의 글자와 쪽별 텍스트 분량을 기록한다. 이 결과만으로 표·그림 내부의 겹침까지 판단할 수는 없으므로 이미지도 확인한다.
- `publish-release.ps1`은 원본 해시를 재확인하고 기존 배포판의 백업을 남긴 뒤 DOCX만 교체한다.

문장을 줄이거나 코드 내용을 바꿔 페이지를 맞추지 않는다. 그림 크기·문단 간격·묶음 처리로 해결하되 인쇄 크기의 가독성을 유지한다. 현재 3.6과 5.5 확인 문항에는 마지막 문항 하나만 다음 쪽으로 밀리지 않도록 간격 조정이 들어 있다.
